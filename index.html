Variables: let, var, const Scoping

var is function-scoped and hoisted (initialised as undefined). let is block-scoped and lives in a temporal dead zone until declaration. const is block-scoped with a fixed binding — but object/array contents remain mutable.

  • Prefer const by default; use let only when reassignment is needed.
  • Never use var in modern code — its hoisting behaviour causes subtle, hard-to-debug issues.
JavaScript
var legacyScore = 10;       // function-scoped, hoisted
let currentLevel = 1;       // block-scoped, reassignable
const MAX_LIVES = 3;         // block-scoped, fixed binding

if (true) {
  var leaked   = "I escape the block"; // accessible outside!
  let contained = "block only";        // ReferenceError outside
}
console.log(leaked);   // "I escape the block"
// console.log(contained); // ❌ ReferenceError

const user = { name: "Alice" };
user.name = "Bob";  // ✅ mutation allowed — only the binding is const
2
Arrow Functions => Lexical this

Arrow functions provide a concise syntax and do not bind their own this — they inherit this from the enclosing lexical scope. Ideal for callbacks and class methods.

  • Cannot be used as constructors (no new).
  • No arguments object — use rest params instead.
JavaScript
// Regular function — 'this' is dynamic (problematic in callbacks)
function Timer() {
  this.seconds = 0;
  setInterval(function() {
    this.seconds++; // ❌ 'this' is undefined in strict mode
  }, 1000);
}

// Arrow function — 'this' is inherited from TimerFixed
function TimerFixed() {
  this.seconds = 0;
  setInterval(() => {
    this.seconds++; // ✅ lexical 'this' from TimerFixed
  }, 1000);
}

// Concise single-expression returns
const double = n => n * 2;
const add    = (a, b) => a + b;

Template Literals ${} Strings

Backtick strings support embedded expressions, multi-line content, and tagged templates — eliminating messy string concatenation.

JavaScript
const product  = { name: "Laptop", price: 999 };
const discount = 0.1;

// Embedded expression + inline calculation
const receipt = `
  Product : ${product.name}
  Price   : $${product.price}
  You save: $${(product.price * discount).toFixed(2)}
`;

// Multi-line HTML fragment
const card = `
  <div class="card">
    <h2>${product.name}</h2>
  </div>
`;

Destructuring Object & Array

Extract values from objects or arrays into distinct variables. Supports renaming, default values, and nested patterns.

JavaScript
// Object destructuring with rename + default
const user = { id: 1, name: "Alice", role: "admin" };
const { name: userName, role, status = "active" } = user;
console.log(userName, role, status); // "Alice" "admin" "active"

// Array destructuring — position-based
const [first, second, ...remaining] = [10, 20, 30, 40];
console.log(first, second, remaining); // 10, 20, [30, 40]

// Nested destructuring
const { address: { city } } = { address: { city: "London" } };

// Function parameter destructuring with default
const greet = ({ name, age = 18 }) => `${name} is ${age}`;
greet({ name: "Bob" }); // "Bob is 18"
5
Spread Operator ... Shallow Copy

Expands an iterable into individual elements. Creates shallow copies — nested objects are still referenced, not cloned.

JavaScript
// Merge arrays
const base     = [1, 2, 3];
const extended = [...base, 4, 5]; // [1, 2, 3, 4, 5]

// Clone + override object (immutable update pattern)
const settings = { theme: "dark", lang: "en" };
const updated  = { ...settings, theme: "light" };
// { theme: "light", lang: "en" }

// Spread in function call
const nums = [3, 1, 7];
const max  = Math.max(...nums); // 7
6
Rest Parameters ... Variadic

Collects all remaining arguments into a real array. Must be the last parameter. Replaces the legacy arguments object (which is array-like, not a real array).

JavaScript
const sum = (...numbers) =>
  numbers.reduce((acc, n) => acc + n, 0);

sum(1, 2, 3, 4); // 10

// First arg is special, rest are collected
const log = (level, ...messages) => {
  messages.forEach(msg => console.log(`[${level}] ${msg}`));
};
log("INFO", "Server started", "Port: 3000");

Default Parameters ES6

Set fallback values directly in the function signature. Defaults activate only when the argument is undefined — passing null does not trigger the default.

JavaScript
const createUser = (
  name,
  role   = "viewer",
  active = true
) => ({ name, role, active });

createUser("Alice");
// { name: "Alice", role: "viewer", active: true }

createUser("Bob", "admin");
// { name: "Bob", role: "admin", active: true }

createUser("Eve", null);
// { name: "Eve", role: null, active: true }  ← null ≠ undefined

Object & Array Methods Built-in

ES6+ ships powerful built-ins to avoid manual loops. Key Object utilities: Object.keys(), Object.values(), Object.entries(), Object.assign(), Object.freeze().

JavaScript
const config = { host: "localhost", port: 5432, ssl: true };

Object.keys(config);    // ["host", "port", "ssl"]
Object.values(config);  // ["localhost", 5432, true]
Object.entries(config); // [["host","localhost"],["port",5432],...]

// Freeze prevents mutation (shallow)
const CONSTANTS = Object.freeze({ PI: 3.14 });
CONSTANTS.PI = 99; // silently ignored (throws in strict mode)

// Array utilities
[1, 2, 3].includes(2);        // true
[1, [2, [3]]].flat(Infinity); // [1, 2, 3]
Array.from("hello");           // ["h","e","l","l","o"]

Modules — import / export ESM

ES Modules enable code splitting and explicit dependency graphs. Each file is its own module scope. Use named exports for multiple items; default export for the primary concern of a file.

JavaScript
// math.js — named exports
export const add      = (a, b) => a + b;
export const subtract = (a, b) => a - b;
export default function multiply(a, b) { return a * b; }

// app.js — import named + default
import multiply, { add, subtract } from './math.js';
console.log(add(2, 3));       // 5
console.log(multiply(4, 5));  // 20

// Rename on import to avoid name conflicts
import { add as addNums } from './math.js';

// Namespace import
import * as MathUtils from './math.js';
10
Promises Async

A Promise represents a future value in one of three states: pending → fulfilled or rejected. Once settled, the state is immutable. Use Promise.all for parallel execution.

JavaScript
const fetchUser = (id) =>
  new Promise((resolve, reject) => {
    if (id > 0) {
      resolve({ id, name: "Alice" }); // fulfilled
    } else {
      reject(new Error("Invalid ID")); // rejected
    }
  });

fetchUser(1)
  .then(user => console.log(user.name))  // "Alice"
  .catch(err  => console.error(err.message))
  .finally(() => console.log("Done"));

// Parallel — waits for ALL to resolve
Promise.all([fetchUser(1), fetchUser(2)])
  .then(([u1, u2]) => console.log(u1, u2));
11
async / await Async

Syntactic sugar over Promises — makes async code read like synchronous code. await can only be used inside an async function. Always wrap in try/catch to handle rejections.

JavaScript
const getPost = async (postId) => {
  try {
    const response = await fetch(`https://api.example.com/posts/${postId}`);

    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }

    const post = await response.json();
    console.log(post.title);
    return post;

  } catch (error) {
    console.error("Fetch failed:", error.message);
    throw error; // re-throw so callers can handle it
  }
};

await getPost(42);

Ternary Operator Conditional

condition ? valueIfTrue : valueIfFalse — compact inline conditional. Avoid nesting ternaries; use if-else for complex logic. Extremely common in JSX rendering.

JavaScript
const isLoggedIn = true;
const greeting   = isLoggedIn ? "Welcome back!" : "Please log in";

// Common in JSX rendering
const button = isLoggedIn
  ? '<button>Logout</button>'
  : '<button>Login</button>';

// Multiple conditions — prefer if-else over deep nesting
const role   = "editor";
const access =
  role === "admin"  ? "full"  :
  role === "editor" ? "write" :
                       "read";

Optional Chaining ?. Null Safety

Safely access deeply nested properties without throwing if an intermediate value is null or undefined. Returns undefined instead of a TypeError. Works with property access, method calls, and array indexing.

JavaScript
const order = {
  id: 101,
  customer: { name: "Alice", address: null }
};

// Without optional chaining — runtime TypeError
// order.customer.address.city ❌

// With optional chaining — returns undefined safely
const city = order?.customer?.address?.city;   // undefined

// Combine with nullish coalescing for fallback
const display = order?.customer?.address?.city ?? "Unknown city";

// Optional method call
order?.customer?.notify?.("Your order shipped");

// Optional array index
const firstItem = order?.items?.[0];
14
ES6 Classes OOP

Syntactic sugar over prototype-based inheritance. Provides a clear structure with constructor, instance methods, static methods, and extends for inheritance. Always call super() in a subclass constructor before using this.

JavaScript
class Animal {
  constructor(name, sound) {
    this.name  = name;
    this.sound = sound;
  }
  speak() { return `${this.name} says ${this.sound}`; }
  static kingdom() { return "Animalia"; } // called on the class itself
}

class Dog extends Animal {
  constructor(name) {
    super(name, "woof"); // must call super first
    this.tricks = [];
  }
  learn(trick) {
    this.tricks.push(trick);
    return this; // enables method chaining
  }
}

const rex = new Dog("Rex");
rex.learn("sit").learn("shake");
console.log(rex.speak());      // "Rex says woof"
console.log(Animal.kingdom()); // "Animalia"

Array Iteration Methods Functional

These methods operate on arrays without mutating the original (except forEach). Each has a specific purpose and return type:

MethodPurposeReturns
map()Transform each elementnew array (same length)
filter()Keep elements passing a testnew (shorter) array
find()First matching elementelement or undefined
forEach()Side effects per elementundefined
reduce()Accumulate to single valueany single value
JavaScript
const products = [
  { id: 1, name: "Shirt",  price: 29, inStock: true  },
  { id: 2, name: "Pants",  price: 59, inStock: false },
  { id: 3, name: "Jacket", price: 99, inStock: true  },
];

const names     = products.map(p => p.name);
// ["Shirt", "Pants", "Jacket"]

const available = products.filter(p => p.inStock);
// [{Shirt}, {Jacket}]

const jacket    = products.find(p => p.name === "Jacket");
// { id: 3, name: "Jacket", ... }

products.forEach(p => console.log(`${p.name}: $${p.price}`));

const total = products
  .filter(p => p.inStock)
  .reduce((sum, p) => sum + p.price, 0); // 128

Objects — Creation, Nesting & Methods Objects

Objects are key-value stores. Use shorthand property names, computed keys, and method shorthand. Object.entries() + reduce() is a powerful pattern for transformations.

JavaScript
// Shorthand property + method shorthand
const name = "Alice", age = 30;
const user = {
  name,          // shorthand for name: name
  age,
  greet() { return `Hi, I'm ${this.name}`; },
};

// Nested access
const company = {
  name: "Acme",
  address: { street: "123 Main St", city: "NY" },
  employees: [{ id: 1, role: "dev" }],
};
company.address.city;       // "NY"
company.employees[0].role; // "dev"

// Dynamic key access
const key = "city";
company.address[key];       // "NY"

// Transform entries: double all prices
const prices  = { shirt: 29, pants: 59 };
const doubled = Object.fromEntries(
  Object.entries(prices).map(([k, v]) => [k, v * 2])
); // { shirt: 58, pants: 118 }

React Hooks (introduced in v16.8) let you use state and lifecycle features in functional components.
Only call at top level Not inside loops or conditions Only from React function components or custom hooks
H1
useState Hook

Definition: Declares a piece of local state in a functional component. Returns a tuple: [currentValue, setterFunction]. Calling the setter triggers a re-render with the new value.

Primary use case: Any UI data that, when changed, should cause the component to re-render — form inputs, toggles, counters, visibility flags.

Example 1 — Basic counter
JSX
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0); // initial value = 0

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+</button>
      <button onClick={() => setCount(count - 1)}>-</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}

Demonstrates the most common pattern — simple numeric state with multiple update actions.

Example 2 — Object state (form fields)
JSX
function LoginForm() {
  const [form, setForm] = useState({ email: '', password: '' });

  const handleChange = ({ target: { name, value } }) =>
    setForm(prev => ({ ...prev, [name]: value })); // preserve other fields

  return (
    <form>
      <input name="email"    value={form.email}    onChange={handleChange} />
      <input name="password" value={form.password} onChange={handleChange} />
    </form>
  );
}

Uses the functional updater form (prev => ...) to safely merge object state — critical when state updates are batched.

H2
useEffect Hook

Definition: Synchronises a component with an external system or side effect (API calls, subscriptions, timers, DOM manipulation). Runs after render. The dependency array controls when it re-runs.

Primary use case: Data fetching on mount, subscribing to events, updating document title, syncing with localStorage.

Example 1 — Fetch data on mount
JSX
import { useState, useEffect } from 'react';

function UserProfile({ userId }) {
  const [user,    setUser]    = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    let cancelled = false; // prevent state update on unmounted component

    const load = async () => {
      const res  = await fetch(`/api/users/${userId}`);
      const data = await res.json();
      if (!cancelled) { setUser(data); setLoading(false); }
    };

    load();
    return () => { cancelled = true; }; // cleanup on unmount
  }, [userId]); // re-runs only when userId changes

  if (loading) return <p>Loading...</p>;
  return <p>{user?.name}</p>;
}

Shows the full data-fetching pattern: dependency array, cleanup function to prevent stale state updates.

Example 2 — Event listener with cleanup
JSX
function WindowSize() {
  const [size, setSize] = useState({
    width:  window.innerWidth,
    height: window.innerHeight
  });

  useEffect(() => {
    const handleResize = () =>
      setSize({ width: window.innerWidth, height: window.innerHeight });

    window.addEventListener('resize', handleResize);
    return () => window.removeEventListener('resize', handleResize); // cleanup!
  }, []); // [] = runs once on mount only

  return <p>{size.width} × {size.height}</p>;
}

Empty dependency array = effect runs once. The cleanup function prevents memory leaks by removing the listener on unmount.

H3
useContext Hook

Definition: Consumes a React Context value without requiring a Consumer wrapper. The component re-renders whenever the context value changes.

Primary use case: Global/cross-cutting state — theme, authentication, locale — that would otherwise require prop drilling through many layers.

Example 1 — Theme toggle
JSX
import { createContext, useContext, useState } from 'react';

const ThemeContext = createContext('light');

export function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light');
  const toggle = () => setTheme(t => t === 'light' ? 'dark' : 'light');
  return (
    <ThemeContext.Provider value={{ theme, toggle }}>
      {children}
    </ThemeContext.Provider>
  );
}

function Header() {
  const { theme, toggle } = useContext(ThemeContext);
  return (
    <header className={theme}>
      <button onClick={toggle}>Switch to {theme === 'light' ? 'dark' : 'light'}</button>
    </header>
  );
}

Standard context pattern: create → provide at root → consume anywhere in the tree without prop drilling.

Example 2 — Auth context with custom hook
JSX
const AuthContext = createContext(null);

export function AuthProvider({ children }) {
  const [currentUser, setCurrentUser] = useState(null);
  const login  = (user) => setCurrentUser(user);
  const logout = ()     => setCurrentUser(null);
  return (
    <AuthContext.Provider value={{ currentUser, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

// Custom hook encapsulates context access + null guard
export function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth must be inside AuthProvider');
  return ctx;
}

function NavBar() {
  const { currentUser, logout } = useAuth();
  return currentUser ? <button onClick={logout}>Logout</button> : null;
}

Best-practice: wrap useContext in a custom hook for type safety, error checking, and a cleaner consumer API.

H4
useRef Hook

Definition: Returns a mutable ref object whose .current property persists for the full lifetime of the component. Changing .current does not trigger a re-render.

Primary use cases: (1) Accessing DOM elements directly — focus, scroll, canvas. (2) Storing mutable values that shouldn't cause re-renders — previous values, timer IDs.

Example 1 — DOM focus management
JSX
import { useRef, useEffect } from 'react';

function SearchBar() {
  const inputRef = useRef(null);

  useEffect(() => {
    inputRef.current?.focus(); // auto-focus on mount
  }, []);

  const clearAndFocus = () => {
    inputRef.current.value = '';
    inputRef.current.focus();
  };

  return (
    <div>
      <input ref={inputRef} placeholder="Search..." />
      <button onClick={clearAndFocus}>Clear</button>
    </div>
  );
}

The ref prop attaches the ref to the DOM element. No re-render is triggered — direct DOM access is used instead.

Example 2 — Previous value tracker
JSX
import { useState, useRef, useEffect } from 'react';

function usePrevious(value) {
  const prevRef = useRef();
  useEffect(() => {
    prevRef.current = value; // store AFTER render → captures previous
  });
  return prevRef.current;
}

function ScoreBoard() {
  const [score, setScore] = useState(0);
  const prevScore         = usePrevious(score);

  return (
    <div>
      <p>Current: {score} | Previous: {prevScore}</p>
      <button onClick={() => setScore(s => s + 10)}>+10</button>
    </div>
  );
}

A reusable custom hook using useRef to remember the previous render's value — the ref update doesn't cause an extra render.

H5
useMemo Hook

Definition: Memoises the result of an expensive calculation. React only recomputes when a value in the dependency array changes.

Primary use case: CPU-expensive transformations (sorting, filtering, aggregating large datasets). Don't over-use — memoisation overhead is only worthwhile for genuinely expensive operations.

Example 1 — Expensive filter/sort
JSX
import { useState, useMemo } from 'react';

function ProductList({ products }) {
  const [searchTerm, setSearchTerm] = useState('');
  const [sortOrder,  setSortOrder]  = useState('asc');

  const filteredProducts = useMemo(() => {
    return products
      .filter(p => p.name.toLowerCase().includes(searchTerm.toLowerCase()))
      .sort((a, b) =>
        sortOrder === 'asc' ? a.price - b.price : b.price - a.price
      );
  }, [products, searchTerm, sortOrder]);

  return (
    <div>
      <input value={searchTerm} onChange={e => setSearchTerm(e.target.value)} />
      {filteredProducts.map(p => <div key={p.id}>{p.name} — ${p.price}</div>)}
    </div>
  );
}

Without useMemo, every unrelated parent re-render would re-run the full sort/filter on the entire list.

Example 2 — Derived statistics
JSX
function SalesDashboard({ orders }) {
  const [filter, setFilter] = useState('all');

  const stats = useMemo(() => {
    const filtered = filter === 'all'
      ? orders
      : orders.filter(o => o.status === filter);

    return {
      count:   filtered.length,
      total:   filtered.reduce((sum, o) => sum + o.total, 0),
      average: filtered.length
        ? filtered.reduce((sum, o) => sum + o.total, 0) / filtered.length
        : 0,
    };
  }, [orders, filter]);

  return (
    <div>
      <p>Orders: {stats.count} | Total: ${stats.total} | Avg: ${stats.average.toFixed(2)}</p>
      <select onChange={e => setFilter(e.target.value)}>
        <option value="all">All</option>
        <option value="paid">Paid</option>
        <option value="pending">Pending</option>
      </select>
    </div>
  );
}

Derives multiple stats in a single memoised pass — all values stay in sync and the calculation runs once per filter/orders change.
